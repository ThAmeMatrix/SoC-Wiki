# 铃兰档案馆 · 离线 Wiki

基于 [BWIKI 铃兰之剑 Wiki](https://wiki.biligame.com/llzj) 的个人离线资料馆。快照日期：**2026-10-23（北京时间）**。

## 打开即可使用

**双击 `index.html`，或在 Windows 上双击 `start.cmd`。**

无需安装、账号、Node.js、Python 或网络。所有正文、搜索索引、样式、脚本和图片都在本地。推荐使用 Edge、Chrome 等现代浏览器。

如果使用压缩包，请先完整解压，再打开 `index.html`。请保留整个文件夹（包括 `assets/`、`data/` 和全部 `.js`、`.css` 文件），不要只复制首页。

**Android**：可安装 `release/SoCwiki-offline-1.18.0.apk`，支持 Android 8.0 及以上。APK 已内置所有离线资料和图片，无需解压或额外下载。初次安装时按系统提示允许当前文件管理器安装应用。收藏与笔记保存在应用中；卸载前请导出备份。构建说明见 `android/README.md`。

## 常用操作

- **搜索**：点击顶栏，或按 `Ctrl+K` / `/`。全站搜索输入即更新，中文输入确认后也会自动搜索，无需点击按钮；右侧「× 清空」有悬停、按下和键盘焦点反馈，清空关键词时保留筛选条件。支持角色别名、全文、模糊与语义匹配；直接输入「持续伤害」「驱散我方减益」「百分比伤害」可关联角色的技能、个性、各星级及抉择分支。用方向键选择结果，按 Enter 打开，Esc 关闭；点击「全部结果与筛选」进入全站搜索页，按分类、武器、多个阵营与命中位置继续筛选。
- **筛选与图鉴**：组合职业、阵营、稀有度或装备类型。角色默认显示像素小人，按原站角色图鉴的顺序排列，支持分页。可切换为含头像、像素形象、职业、阵营、武器与六项满级满星属性的“单位列表”；点击数值表头升降序排列，小屏可横向滚动，两种视图共享筛选条件。
- **角色立绘**：角色页直接切换初始立绘、觉醒立绘（五星）及已归档皮肤，点击立绘可放大和保存。原站缺少的立绘明确提示，不用其他图片冒充。
- **角色属性**：切换初始 / 满级满星属性，查看技能树、故事和原文。支持精英稀有度筛选；从原文补全旧式页面的属性，召唤物的继承属性按原值展示。
- **个性星级**：默认“五星对照”，公共效果单独展示，下方依次列出 1–5 星的其余完整文本。公共效果与该星文本共同构成完整个性。底色和下划线标记变化：1 星标出后续会成长的部分，后续星级标出相较上一已收录星级的调整；移除的文字另行标记。保留原文颜色和原有词条链接，也可切回“单星全文”。仅提取五个星级完全相同的完整句子作为公共效果，缺少星级时不推算。
- **技能成长树**：进入角色的“技能与成长”，技能树从下向上生长，11 阶在顶部、1 阶和初始技能在底部。1、3、5、7、11 阶呈左右分支，9 阶单列为普攻进阶。点选技能可在本页查看消耗、冷却、标色效果和范围图；桌面在右侧展示，小屏在选中节点下展开。
- **技能范围图**：所有技能（成长树详情、技能独立页、装备星级技能、抉择分支预览）统一使用同一套**蓝底标识可施法射程、红底标识作用范围**的示意图，由 `socdecode.ranges` 依据客户端 `target_select`、射程与描述里的形状词绘制，点击可放大。原先技能页用的是客户端战斗格贴图（橙色小图标）、抉择页用扁平蓝/红图，现已归一；原站收录的范围图由客户端示意图取代，无法判定形状时保留文字说明而不猜。每次「开始更新」后会自动重绘（`scripts/rebuild_range_images.py`），单独运行也支持 `--dry-run`。
- **装备**：1–5 星技能效果使用与角色个性完全相同的「五星对照 / 单星全文」差分：公共效果单独列出，变化文字用底色与下划线标出，未收录的星级明确提示；原站页面缺差分的会在每次重建时自动补齐。带技能的装备另有「星级技能详情」，按角色技能页的方式列出技能名、类别、消耗、冷却、射程、范围、图标与范围图，可切换星级查看对应技能。查阅来源与适合角色；在“装备属性参考”按类型、稀有度查看满级满星基础属性。
- **抉择技能与机制规则**：抉择技能（如阿坎贝「一掷千金」）在角色详情的「技能与成长」页里，描述中的 `[人为财死]` / `[重赏之下]` 词条**点击就直接进入对应技能词条页**，不必先打开抉择技能页再二次跳转；鼠标悬停仍显示原来的「中括号介绍」效果说明（链接 href 保持不变）。抉择技能页本身列出全部可选分支：每张卡片带客户端技能图标、消耗 / 冷却 / 射程 / 类别，展开「预览技能效果与作用范围」可看到**技能效果原文、客户端机制摘要与作用范围图**，点标题或底部链接进入完整词条页；分支页也有返回父技能的链接。分支关系取自客户端 `speciality` 表的 `SKILL_GROUP`（type 158）参数，不是从描述文字猜的；图标来自 `image/icon/skill/`，范围图由 `socdecode.ranges` 按与技能页相同的规则绘制。
  侧栏「机制规则」收录约 1,200 个**权威词条**：客户端 `skill` 表为同名技能存了活动版、二段施法、星级强化等多行配置（2,237 个重名），过去按名字放行会导致搜一个名字冒出十几张几乎一样的卡片。现在按「抉择分支 → `client-data.json` 角色技能树 → 客户端技能页 `clientSource.rowId` → 原站技能描述相符度」判定真正生效的那一行，**每个名字只出一个词条**，并标注权威依据与置信度；其余 1,383 个同名变体折叠在「查看同名变体」里，仍可查 id、编辑名与射程。规则本身把 `speciality_ids` 特效链按 `speciality_type`（257 种）、`aoe_param`、`aoe_diffusion_mode`、`range_select`、`buff` 反解，每条按「结论 → 详细解释 → 配置表原文 → 来源行号」四层呈现，并保留技能描述原文与完整特效链，解释文本也纳入全文搜索。搜索框常驻、只在结果区重绘，并正确处理输入法组合事件，**可以连续输入中文**；同时支持本项目同一套拼音索引（`pypinyin` 生成的全拼与首字母），输入 `rwcs` 或 `renweicaisi` 可找到「人为财死」、`yzqj` 找到「一掷千金」。例如「人为财死」的聚拢规则是：以目标地形格为原点、菱形 3 格（中心向外、高差 2）选中敌人，再由 `OTHER_TELEPORT_TO_TARGET`（方向比特位 15 = 上下左右四方向）把这些单位传送到目标格身边、按中心向外顺序就近落位，同时施加 ▼移动2、▼魔防2、✕援护。
- **战斗地图**：侧栏「战斗地图」解析客户端 `map` / `weather` / `sound` 表，展示 632 张战斗地图的模型、天气（含效果说明）、时段、BGM 与地形网格。网格由 `map.data` 的 protobuf 地块数据解码（12.5 万个格子，坐标与地形编号直接用客户端字段，不做推测），默认只显示带网格的地图；地形名称、通行性与效果说明取自客户端 `field_type` 表（30 种，如土地 / 草地 / 深水 / 禁行），地形块直接使用客户端 `terrain_atlas.unity3d` 解出的 42 张贴图（27 个 `field_type.icon` 全部命中，草地显示绿色草地块、水面显示蓝色水块），2D 用 SVG pattern、3D 用 CSS 背景；页面顶部只留一行紧凑工具栏，说明与数据概览收进「说明」弹出层。关卡名取自 `mini_sandbox_capital_area.map_id` 与 `online_rogue_map_chain.map_ids` 的关联（76 张地图有中文名），并从模型名解析出平原 / 城市 / 山地 / 白天 / 夜晚等场景标签。**默认 3D 等距立体显示**（按客户端高度标记抬高地块、绘制明暗侧面），可一键切换 2D 俯视；2D 视图格子放大并配深色棋盘底、坐标轴、网格线与高对比地形配色，白框与数字表示客户端高度标记，支持逐图 / 全部缩放、按地形名显隐、悬停查看坐标 / 地形效果 / 高度，以及弹窗大图。3D 图改为**固定尺寸显示框 + CSS 3D 相机**（直接参考 `D:\Workspace\SoCxiezhouTool\app\js\map.js` 的 `rotateX(--tilt) rotateZ(--yaw)` + `perspective:1600px` + `preserve-3d`）：框固定 360px 高，拖动可同时水平转（yaw）与上下俯仰（tilt 0–85°），方向与参考工具一致（拖右 yaw 减小、拖上 tilt 增大），滚轮缩放 40%–200%，并有「重置视角」；深度遮挡交给浏览器原生 3D 排序，不再用 SVG 重投影，任意角度都不会错位；立柱高度与侧壁直接体现客户端高度标记（1 层 ≈ 2）；页面头部（说明、工具栏、数据概览）为粘性固定，滚动时不移动。网格 y 坐标原本按客户端的 2 格步长存储却被当作 1 格解码，导致每隔一行空白，现已整除修正。搜索支持关卡名、场景标签、地形中文名与效果说明、`field_status` 地形状态（如「冰冻」「燃烧」按可燃地形关联）以及模型 / 天气 / id。
- **自动战斗 AI**：侧栏「自动战斗 AI」除优先级机制外，新增「**如何选走路路径、技能如何选人**」分析：移动能力（`unit.mobility` 多为 3 格、`jump_up/jump_down`、`move_type` 钝步/轻步/飞行/瞬移/不可移动）、地形通行代价（`field_type.mobility` 一般 10、流沙 20、禁行 0、虚空 1000，另有雨天值与状态额外消耗）、站位偏好（`ai_move_close` 与 `map:getNeighborUnitCount` / `findChargeBlock` / `CheckShadowStepValid`）、目标四层打分（`target_method` 18 类 → `range_select` 11 种形状 + 射程 → 638 段 `target_param` 过滤 Lua → `target_order_param` 排序 Lua）。结论：配置表能查到全部输入与打分脚本，但最短路求解器在编译代码中。侧栏「自动战斗 AI」解析客户端 `unit_npc` / `skill` / `unit_personality` 表，展示 8,114 个单位的自动战斗行动逻辑：技能选择顺序（按顺序 / 按优先级 / 默认）、BOSS 固定技能序列携带技能与个性；另有 14 个技能的 `ai_order_param` **Lua 决策脚本原文**（含 `owner` / `map` 与返回权重），可按单位名、个性或脚本内容搜索。AI 页另加四项统计卡、按 BOSS 序列长度优先排序的单位卡片、逐步行动时间线、决策类型标签与 Lua 语法高亮，并可按决策类型筛选。

前端使用原生 HTML / CSS / JavaScript，没有运行时第三方库。页面按需加载为本地脚本，避免 `file://` 的 fetch / CORS 限制。正文经过清洗，移除原站脚本、表单、事件处理器和远程嵌入；CSP 限制运行时联网与脚本执行。

## 本地客户端更新（SoCdecode 已并入本项目）

本地工具做两件事：**资源归档**——把本机铃兰之剑客户端里的全部资源解析成可直接查看的文件，按分类整理，并以解析时间记录版本、自动生成差分；**Wiki 更新**——把角色词条、技能、个性、专武与关联状态写入这个离线资料馆。解码逻辑在 `scripts/socdecode/`，网页与 APK 本身不需要 Python。

**图形界面（推荐）**：双击根目录 `本地更新.cmd`（不会留下黑色控制台窗口），或运行打包出的 `dist/SoCwiki本地更新.exe`。界面沿用资料馆的配色，左侧四个页面，`Ctrl+1–4` 切换：

- **更新资料馆**：日常只需要这一页。顶部三张卡片显示客户端是否就绪、资料馆收录了多少角色、上次更新时间。选「差量更新」（只补缺失与空白字段，手动修改与署名保留）或「全覆盖」，点 **开始更新** 即可，其余全部自动完成：读取客户端（未变化时直接复用缓存）→ 生成页面 → 写入并备份 → 重建索引（含补齐装备星级差分）→ 提取像素动作 / 立绘表情 / 局外面板数值 / 剧情对话。进度条上方的步骤条逐项显示完成情况；结束后出现结果卡片，列出角色、页面、图片、字段差异与缺失原资源数，并提供「在浏览器中打开资料馆」「查看更新报告」「回滚本次更新」。「更多选项」里可以改用之前读取过的客户端版本、关闭索引重建或衍生资源提取、额外提取角色语音、强制重新解析客户端（同时强制重建像素动作与表情资源）。衍生资源**不需要先做「资源归档」**：`extract_art.py` 会优先复用 `output/archive`，没有归档时直接用 UnityPy 读取客户端自带的 `share/tex`、`battle/unit`、`icon/face` 与 `ui/dynamic_card_full` 资源包；资源已完整时自动跳过，找不到客户端时保留随包资源并正常结束，绝不会用空索引覆盖已有图片。单独运行可用 `--source archive|client` 与 `--force`。剧情对话由 `extract_dialogues.py` 生成：优先读 `output/archive/library/当前版本/配置表` 里已解密的 `translation` / `performance` / `scenario` 表，没有归档时直接用 Lua 解析器读客户端 `lua_dbtemplate*.unity3d`（约 12 秒），按 `idvalue` 配对台词与说话人、按剧情线分组，并复用「立绘表情」索引；可用 `--source archive|client --dry-run` 检查，找不到客户端时保留 `data/dialogues.js` 不变。「重新提取角色语音」是可选步骤，依赖 `tools/vgmstream/` 里的 `vgmstream-cli.exe` 与同目录 DLL（已随资料包提供，许可见该目录的 `COPYING`）；从旧版 ZIP 解压、缺少该目录时，脚本会打印下载与放置位置并**跳过**，不会让更新失败，也不会覆盖已有语音。`extract_voices.py` 单独运行后需另行执行 `socdecode.rebuild.rebuild_voices` 生成 `data/voices.js`，用界面更新则会自动完成。下方「其他操作」提供检查新角色、补充新角色、预览变更（不写入）与回滚上次更新。运行日志默认折叠，标题行始终显示最新一行，出错时自动展开。
- **资源归档**：勾选解析范围（12 个分类）与并行进程数，点「开始解析」。前四个阶段（扫描 → 比对上次结果 → 解析 → 生成版本与差分）以步骤条显示，并实时给出吞吐量、剩余时间、新写入与复用数；可随时取消，已完成的部分下次直接复用。与上一版本不同时以当前时间生成新版本并提示查看差分；完全相同则不生成。**资源只保存一份**：解析结果按内容指纹写入 `output/archive/objects/`，资源浏览器、差分与其它工具都直接读它；「整理分类目录」只是给资源管理器人工浏览的硬链接树，默认关闭，不需要它也能正常浏览。**硬链接失败不再回退成复制**（跨盘或非 NTFS 时跳过并提示），版本库显示真实占用并区分「硬链接目录项（不额外占空间）」与真实副本，缩略图缓存也纳入清理与统计。「清理分类目录」可一键删掉已有的目录树，资源本体与版本记录保持不变。

- **设置**：客户端目录（支持自动识别并即时校验）、资源归档目录、资料馆位置，以及日志、备份与上次更新报告的入口。所有选择自动保存。

界面流程回归：`python -X utf8 scripts/verify_updater_gui.py`（「检查新角色」真实运行，更新流程在临时目录中模拟，不改动资料馆）。

**资源浏览器**（「打开资源浏览器」，或 `archive serve`，只监听 127.0.0.1）：左侧版本时间线（每个版本的变化徽标，一键设为基准 / 目标或对比上一版），中间分类树与可搜索、可分页的资源列表，右侧预览与差分。

- 预览：图片（棋盘格背景、原始大小）、配置表（分页、全文搜索）、文本 / JSON（行号）、视频、字体样张、模型线框（可旋转缩放）、二进制十六进制视图；可下载或在文件夹中定位原文件。
- 差分：版本概览按分类给出新增 / 修改 / 删除 / 改名与体积变化；图片支持并排、滑动对比、闪烁与差异高亮（标出变化像素数量与范围）；配置表按主键逐行、逐字段列出修改前后值，以及新增 / 删除的行与列；文本逐行并排对比并高亮行内改动；内容相同、路径不同的资源识别为改名；另列客户端原始文件的增删改。
- 地址栏保留当前版本、分类、筛选与选中资源，可直接分享或用前进 / 后退切换；`/` 聚焦搜索，`↑↓` 切换资源，`Esc` 回到概览；明暗主题。

**归档内容与分类**：配置表（全部 1,249 张客户端配置表解码为 JSON，含主键与行列数）、图片（Texture2D，PNG）、精灵（Sprite 裁切）、文本、数据（不可读的 TextAsset 与带容器路径的 MonoBehaviour 结构）、脚本（Lua 字节码）、音频（Wwise `.wem` / `.bnk`，客户端已加密，只做存档与变化比较）、视频（`.mp4`）、字体、模型（OBJ）、资源包清单（每个资源包的对象构成）、程序文件。当前客户端（资源版本 6265075，49,023 个文件，9.1 GB）解析为 177,277 项资源。账号记录、启动器数据库、战斗回放（`assets/Report`）与玩家偏好设置始终不读取。

**存储与性能**：每项资源按内容指纹只保存一份（`output/archive/objects/`，只读），版本只记录「路径 → 指纹」清单，因此多个版本共享未变的资源，新版本只占用变化部分的空间。`library/当前版本/` 是按「分类 / 位置 / 文件名」整理的目录，由硬链接组成，不额外占用空间，每次解析后只更新变化的文件；任意版本都可另外导出成同样的目录。解析在多进程中并行；每个客户端文件的解析结果按内容缓存，未变的文件不再解析。本机实测（20 线程 CPU）：首次完整解析 9.1 GB 约 5.5 分钟，首次建立分类目录另需约 3 分钟；客户端未变时重新检查约 2.5 秒；部分更新只解析变化的文件。

**命令行**：

```powershell
python -X utf8 scripts/update_client.py archive scan                 # 解析全部资源；有变化才生成新版本（--only table,image 只解析部分分类）
python -X utf8 scripts/update_client.py archive versions             # 列出全部版本
python -X utf8 scripts/update_client.py archive diff [基准] [目标]   # 比较任意两个版本（省略则为最新与上一版）
python -X utf8 scripts/update_client.py archive serve                # 打开资源浏览器
python -X utf8 scripts/update_client.py archive export <版本> [目录] # 把某个版本导出为分类目录（硬链接）
python -X utf8 scripts/update_client.py archive delete <版本>        # 删除版本记录；随后 archive gc 释放空间
python -X utf8 scripts/update_client.py characters --missing         # 客户端有、Wiki 还没有的角色
python -X utf8 scripts/update_client.py add --character 君士坦丁     # 导入一个角色（--dry-run 只看差异）
python -X utf8 scripts/update_client.py diff                         # Wiki 差量更新
python -X utf8 scripts/update_client.py full                         # Wiki 全覆盖
python -X utf8 scripts/update_client.py rollback "<备份目录>"        # 回滚一次 Wiki 更新
```

**规则与边界**：需要 Windows x64 与 Python 3.10+；只读取客户端文件，不登录、不启动游戏。配置表在隔离的 Lua 环境中由客户端自带的运行库解码（无文件、进程与网络能力）。某个文件导致解析进程崩溃时会自动重启进程并逐个重试，仍失败的文件记入版本记录而不中断整个解析；无法解码的对象只记录指纹，同样参与比较。Wiki 更新每次写入前在 `output/backups/时间-编号/` 保存逐文件备份与变动报告，重复运行相同数据不会改动文件；写入失败自动恢复，`rollback` 只操作该次更新的文件。属性按客户端 `PlayerRoleUnit.CalculateAttributeByType` 的整数截断顺序计算（60 级、五星、13 阶、左右技能全解锁），不含装备、天赋、好感与模组加成。技能范围图只绘制字段或描述惯例能确定的形状。

**注意**：Wiki 更新会直接把新页面合并进 `data/index.js`、`data/search.js` 与 `data/advanced-search.js`。`scripts/build_data.py` 只从 `data/raw` 重建这些索引，会清掉客户端写入的条目，因此客户端更新后不要运行它（本工具自带的重建只跑 `scripts/build_infographic.py --metadata-only`）。`output/`（归档、缓存、报告、备份）已加入 `.gitignore`。
